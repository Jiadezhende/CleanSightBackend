# 启动与验收

仅在用户要求启动时执行；用户已明确要求启动时，不重复请求同一授权。创建或修改本 skill 不启动业务服务。

预检完成后，在项目根目录使用已有入口：

```bash
bash start_backend.sh
```

Windows PowerShell 使用 `.\start_backend.ps1`。PPU 先加载厂商 envsetup.sh。启动脚本只运行后端，daemon 从 Settings 读取端口并传给 MediaMTX 子进程，所有实例关闭 reload。

已有服务占用时先确认归属和用户意图，不擅自清理。使用平台已有进程托管方式；需自行后台运行时记录本次 PID／进程组、日志和停止方式，Windows 使用隐藏窗口，避免终端退出使服务丢失。

验收确认本次实例存活、健康接口正常、mediamtx 状态为 running 及模型加载成功。日志筛查 warmup、worker ready 和加载异常，避免把旧实例响应或仅有 HTTP 200 当成推理就绪。若现有接口无法证明所需能力，明确缺口，并按用户要求执行样本推流或离线任务验证。

真实任务、外部上报、迁移或停止其他实例遵循用户授权。失败时正常停止本次实例、修复并重启，只复查受影响项。最终报告启动与停止方法、实际通过的检查，以及尚未验证的能力；只展示必要脱敏信息。

MediaMTX 重试耗尽时 RTSP 入口关闭，/health/status 返回 503 和 degraded，后端与已有离线任务继续运行。先按脱敏 error_code 排查；正常停止并重启实例以恢复 daemon，不将健康故障误判为整个后端已退出。
