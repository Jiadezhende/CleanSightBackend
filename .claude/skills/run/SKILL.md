# CleanSight 运行配置与启动

仅在用户显式输入 `/run <任务>` 时启用。默认当前项目与机器，远程目标需用户提供访问方式和目录。依据用户任务执行配置、检查或启动；已经明确要求启动时直接推进，缺信息或已有实例冲突时再询问。

## 执行流程

1. **准备配置**。按 [配置说明](references/runtime-config.md) 使用单份 `config/settings.yaml`，已有配置保留，缺失时从模板创建。缺依赖时转交显式 `/install`。
2. **一次预检**。按 [检查要点](references/service-checks.md) 复用 `app.settings` 和现有服务配置加载器，核对配置、模型、资源；启动任务同时检查数据库与端口。汇总本轮可发现的问题，修复后只复查受影响项。
3. **启动并确认就绪**。按 [启动说明](references/startup.md) 使用项目已有入口，确认本次实例、健康和模型加载状态。业务推流、离线作业等按用户要求验证，报告实际证据与剩余缺口。

Agent 根据目标平台生成检查命令即可。临时脚本放在目标机临时目录，完成后清理；不在仓库固化一次性检查，不重复实现 Settings 或服务配置解析。

只输出必要的脱敏状态，凭据由用户在目标机填写。用户只要求配置或检查时不自行启动；停止既有实例、覆盖配置、数据库迁移和有副作用的业务测试遵循本次授权。固定容器优先使用平台已有托管方式，并记录本次实例的日志与停止方法。
