# Persistence模块开发上下文

## 模块概述

独立的持久化模块，负责异步处理所有耗时的持久化操作（磁盘写入、HTTP上报、数据库写入），避免阻塞主推理流程。

**核心原则**：
- InferenceManager只负责收集数据+提交到队列
- Persistence模块独立处理所有入库和写盘操作
- 使用策略模式+Worker池模式实现

## 架构设计

```
PersistenceManager (协调器)
    ├── HLSWorkerPool (2线程) → HLSPersistenceStrategy
    │   └── 处理：MP4编码、M3U8生成、keypoints JSON、metadata更新
    └── AlarmWorkerPool (1线程+flush) → AlarmPersistenceStrategy
        └── 处理：批量去重、HTTP上报、数据库记录、冷却期管理
```

## 文件结构

```
app/services/persistence/
├── .claude.md              # 本文件（AI上下文）
├── __init__.py             # 导出：PersistenceManager, PersistenceConfig
├── manager.py              # 核心协调器
├── models.py               # HLSPersistenceTask, AlarmPersistenceTask
├── config.py               # PersistenceConfig（从环境变量加载）
├── strategies/
│   ├── hls_strategy.py     # HLS持久化逻辑（从InferenceManager迁移）
│   └── alarm_strategy.py   # 告警持久化逻辑（批量+去重+重试）
└── workers/
    ├── hls_worker.py       # HLS Worker池（2个并发线程）
    └── alarm_worker.py     # 告警Worker池（1个flush+1个上报）
```

## 核心组件

### 1. PersistenceManager (manager.py)

**职责**：统一入口，协调所有持久化策略

**公开API**：
```python
# 初始化
config = PersistenceConfig.from_settings()
manager = PersistenceManager(config)

# 启动/停止
manager.start()
manager.stop(timeout=10.0)

# HLS持久化（InferenceManager调用）
manager.persist_hls_segment(
    client_id="client_1",
    task_id=123,
    segment_type="raw" | "processed",
    frames=[FrameData(...), ...]
)

# 告警持久化（InferenceManager调用）
manager.persist_alarm({
    'task_id': 123,
    'step_id': 2,
    'client_id': 'client_1',
    'alarm_type': '流程违规',
    'alarm_level': 'high',
    'alarm_message': 'AI推理检测到异常',
    'detection_result': {...}
})

# 获取指标
metrics = manager.get_metrics()
```

**内部结构**：
```python
class PersistenceManager:
    # 队列
    hls_queue: Queue[HLSPersistenceTask]      # maxsize=256
    alarm_queue: Queue[AlarmPersistenceTask]  # maxsize=128

    # Worker池
    hls_pool: HLSWorkerPool        # 2个Worker线程
    alarm_pool: AlarmWorkerPool    # 1个flush线程 + 1个上报线程

    # 策略
    hls_strategy: HLSPersistenceStrategy
    alarm_strategy: AlarmPersistenceStrategy
```

### 2. HLS持久化策略

**HLSPersistenceStrategy** (strategies/hls_strategy.py)

**负责**：
- 编码MP4视频段（raw: 30fps, processed: 20fps）
- 生成M3U8播放列表
- 序列化keypoints JSON
- 更新metadata.json（统计信息）

**配置**：
```python
storage_base_dir = Path("./database")
raw_fps = 30.0           # 原始视频帧率
processed_fps = 20.0     # 推理视频帧率
```

**文件组织**：
```
database/
└── {client_id}/
    └── {task_id}/
        ├── raw_segment_1234567890.mp4
        ├── raw_playlist.m3u8
        ├── processed_segment_1234567890.mp4
        ├── processed_playlist.m3u8
        ├── keypoints_1234567890.json
        └── metadata.json  # HLS统计信息（不存数据库）
```

**metadata.json格式**：
```json
{
  "raw": {
    "segment_count": 10,
    "total_duration": 100.5,
    "last_update": 1234567890.123
  },
  "processed": {
    "segment_count": 10,
    "total_duration": 100.5,
    "last_update": 1234567890.123
  }
}
```

**HLSWorkerPool** (workers/hls_worker.py)
- 2个并发Worker线程
- 从hls_queue消费任务
- 调用HLSPersistenceStrategy执行

### 3. 告警持久化策略

**AlarmPersistenceStrategy** (strategies/alarm_strategy.py)

**负责**：
- 批量聚合（30秒间隔）
- 去重（相同告警key）
- 冷却期管理（60秒内不重复上报）
- HTTP上报（带重试，指数退避：1s→2s→4s）
- 数据库记录（clean_alarm表）

**告警去重key**：`{task_id}_{step_id}_{alarm_type}`

**配置**：
```python
batch_interval = 30        # 批量间隔（秒）
cooldown_seconds = 60      # 冷却期（秒）
retry_times = 3            # HTTP重试次数
```

**AlarmWorkerPool** (workers/alarm_worker.py)
- 1个AlarmFlushThread：每30秒聚合原始告警
- 1个AlarmWorker：处理聚合后的告警（HTTP+DB）

**聚合逻辑**：
```python
# 30秒内收到5个相同告警 → 聚合为1个
{
    'task_id': 123,
    'alarm_type': 'leak_detected',
    'alarm_count': 5,              # 聚合计数
    'first_seen': '2026-01-26 10:00:00',
    'last_seen': '2026-01-26 10:00:30'
}
```

### 4. 数据模型 (models.py)

```python
@dataclass
class HLSPersistenceTask:
    client_id: str
    task_id: int
    segment_type: str          # "raw" | "processed"
    frames: List[FrameData]
    timestamp: float

@dataclass
class AlarmPersistenceTask:
    task_id: Optional[int]
    step_id: Optional[int]
    client_id: str
    alarm_type: str
    alarm_level: str           # "high" | "medium" | "low"
    alarm_message: str
    detection_result: Optional[Dict[str, Any]]
    timestamp: float

    def get_key(self) -> str:
        """告警去重key"""
        return f"{self.task_id}_{self.step_id}_{self.alarm_type}"
```

## 与InferenceManager的集成

**InferenceManager职责**：
- ✅ 收集数据（帧达到300个时）
- ✅ 提交到persistence队列（persist_hls_segment, persist_alarm）
- ❌ 不再负责：MP4编码、M3U8生成、HTTP上报、数据库写入

**调用点**：

1. **HLS持久化**：
```python
# InferenceManager._enqueue_raw_segment_job()
self.persistence_manager.persist_hls_segment(
    client_id=client_id,
    task_id=task_id,
    segment_type="raw",
    frames=raw_frames_data
)

# InferenceManager._enqueue_processed_segment_job()
self.persistence_manager.persist_hls_segment(
    client_id=client_id,
    task_id=task_id,
    segment_type="processed",
    frames=processed_frames_data
)
```

2. **告警持久化**：
```python
# InferenceManager.enqueue_alarm()
self.persistence_manager.persist_alarm(alarm_info)
```

### 快速步骤

1. **定义任务模型** (models.py)

```python
class NewPersistenceTask:

```

2. **实现策略类** (strategies/new_strategy.py)
```python
class NewPersistenceStrategy:
    def __init__(self, config_param: str):
        self.config = config_param
        logger.info("NewStrategy已初始化")

    def persist_data(self, client_id: str, data: Any) -> bool:
        try:
            # 实现持久化逻辑
            logger.info("数据已持久化: %s", client_id)
            return True
        except Exception as e:
            logger.error("持久化失败: %s", e, exc_info=True)
            return False
```

3. **实现Worker池** (workers/new_worker.py)
```python
class NewWorker(threading.Thread):
    def run(self):
        logger.info("NewWorker-%d 已启动", self.worker_id)
        while not self.stop_event.is_set():
            try:
                task = self.input_queue.get(timeout=0.5)
                self.strategy.persist_data(task.client_id, task.data)
            except Empty:
                continue
        logger.info("NewWorker-%d 已停止", self.worker_id)

class NewWorkerPool:
    def start(self): ...
    def stop(self, timeout=10.0): ...
```

4. **集成到Manager** (manager.py)
```python
class PersistenceManager:
    def __init__(self, config):
        # 创建队列和Worker池
        self.new_queue = queue.Queue(maxsize=256)
        self.new_pool = NewWorkerPool(...)

    def persist_new_data(self, client_id: str, data: Any) -> bool:
        """新的公开API"""
        task = NewPersistenceTask(client_id=client_id, data=data)
        try:
            self.new_queue.put_nowait(task)
            return True
        except queue.Full:
            logger.warning("新队列已满")
            return False

    def start(self):
        self.hls_pool.start()
        self.alarm_pool.start()
        self.new_pool.start()  # 新增

    def stop(self, timeout=10.0):
        self.hls_pool.stop(timeout)
        self.alarm_pool.stop(timeout)
        self.new_pool.stop(timeout)  # 新增
```

5. **更新配置** (config.py)
```python

    new_workers: int = 2
    new_config_param: str = "default_value"
```

## 最佳实践

### 队列容量设计
```python
高频操作（HLS）    → maxsize=256
中频操作（告警）   → maxsize=128
低频操作（清理）   → maxsize=64
```

### Worker数量配置
```python
CPU密集型（编码） → 2-4个Worker（匹配CPU核心数）
IO密集型（HTTP）  → 1-2个Worker（避免过度并发）
```

### 超时设计
```python
队列取任务    → timeout=0.5秒（定期检查stop_event）
数据库操作    → timeout=5.0秒
HTTP请求      → timeout=10.0秒
Worker停止    → timeout=10.0秒
```

### 异常处理
```python
# ✅ 推荐：捕获具体异常
try:
    self.db_client.write(data)
except ConnectionError as e:
    logger.error("数据库连接失败: %s", e)
    return False
except Exception as e:
    logger.error("未知错误: %s", e, exc_info=True)
    return False

# ❌ 避免：静默失败
try:
    self.db_client.write(data)
except:
    pass
```

### 优雅停止
```python
def run(self):
    while not self.stop_event.is_set():  # 检查停止信号
        try:
            task = self.queue.get(timeout=0.5)
            self.process(task)
        except Empty:
            continue  # 超时后继续检查stop_event
```

## 常见问题

### Q1: 队列满导致任务丢失
**解决**：增加队列容量或Worker数量

### Q2: Worker线程卡死
**排查**：检查是否有阻塞操作未设置超时

### Q3: 内存泄漏
**排查**：检查队列是否无限增长，限制单次任务数据量

### Q4: 数据库连接池耗尽
**解决**：使用连接池并设置max_connections
